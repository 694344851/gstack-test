## Problem Statement

`我的作品库` 现在只有卡片墙。用户可以看到作品已经存在，但点开之后没有一个真正可操作的作品详情层。

这次要解决的问题不是“给卡片加个详情页”，而是：

把每一首作品变成一个可以被查看、播放、管理的创作资产。

这个详情层需要满足四件事：

- 点击作品后优先用**弹窗**承接，不打断作品库上下文
- 不做时间轴回放，而是直接展示每个创作节点的内容
- 在同一层里提供 `播放 / 重命名 / 删除`
- 删除进入**垃圾箱**，并支持恢复

## What Makes This Cool

真正让这块成立的，不是“我有历史记录”，而是：

- 一首作品在库里不只是卡片，而是可管理的对象
- 点开后能立刻看到这首作品的成品和它的创作剖面
- 删除不再是危险的一次性动作，而是有信任感的资产管理流程

“哇” 的瞬间应该是：

“这不是一排历史卡片，而是一个我能继续管理、继续理解的作品库。”

## Constraints

- 延续当前项目的桌面优先工作台结构和 `DESIGN.md` 视觉方向
- 详情承载方式优先是弹窗，不新增跳转页
- 不做流程回放动画，只展示各节点静态内容
- 作品级操作必须包含：
  - 播放
  - 重命名
  - 删除到垃圾箱
  - 从垃圾箱恢复
- 当前数据仍应尽量复用 `generation_tasks`，避免无必要的新持久化模型
- 本期不要求批量操作、筛选、排序、系列分组

## Premises

1. 作品详情应该是弹窗，不是新页面，因为用户需要保留作品库上下文。 — agree
2. 详情主体应该是“节点静态查看”，不是“流程回放”。 — agree
3. `播放 / 重命名 / 删除` 应该放在详情弹窗顶部，作为作品级主操作。 — agree
4. 删除不做立即物理删除，而是先进入垃圾箱，并提供恢复。 — agree
5. `generation_tasks` 仍然是作品详情的事实来源，垃圾箱语义应尽量在现有持久化模型上扩展。 — agree

## Approaches Considered

### Approach A: 最小详情弹窗

Summary:
点击卡片后打开弹窗，顶部提供播放、重命名、删除；主体只展示各节点的简化摘要。删除后仅提供短暂撤销，不做真实垃圾箱。

Effort: Medium
Risk: Low

Pros:
- 最快落地
- 改动最少
- 能立刻让卡片“点得开”

Cons:
- 删除语义不完整
- 资产信任感不够
- 后面补垃圾箱时还要再改一次结构

Reuses:
- 现有作品库卡片墙
- 现有 `generation_tasks` 完整快照
- 现有节点渲染结构

### Approach B: 详情弹窗 + 节点剖面 + 轻量垃圾箱

Summary:
点击卡片后打开大尺寸详情弹窗。顶部是作品主信息和 `播放 / 重命名 / 删除`；主体展示节点列表与节点详情。删除进入垃圾箱，作品库增加垃圾箱入口，支持恢复。

Effort: Medium-Large
Risk: Low-Medium

Pros:
- 最符合当前需求
- 一次把作品查看与作品管理做完整
- 删除/恢复语义清晰，产品信任感更强
- 保留工作台感，不会退化成普通媒体库

Cons:
- 需要增加垃圾箱状态和垃圾箱列表
- 需要补充详情读接口与更新接口
- 弹窗信息密度高，对布局要求更严格

Reuses:
- 现有 `generation_tasks` 持久化
- 现有 `GET /library/works`
- 现有阶段顺序、stage artifact、`current_result`
- 现有音频播放能力

### Approach C: 详情弹窗 + 独立垃圾箱管理区

Summary:
作品详情弹窗保留查看和管理；垃圾箱做成作品库内独立子页面或独立二级视图，支持更完整的管理动作。

Effort: Large
Risk: Medium

Pros:
- 管理能力最完整
- 后续扩展批量恢复、批量清空更顺
- 更接近成熟资产系统

Cons:
- 对当前阶段偏重
- 容易把作品库做成后台管理页面
- 会稀释“点开作品就有完整信息”的主价值

Reuses:
- Approach B 的全部能力
- 额外垃圾箱视图层

## Recommended Approach

选择 **Approach B: 详情弹窗 + 节点剖面 + 轻量垃圾箱**。

这是当前最合适的解法，因为它一次性解决了三个关键缺口：

1. 作品卡片终于能打开成真正的作品详情层
2. 每个创作节点都有稳定展示位，但不需要做复杂的回放模型
3. 删除从高风险动作变成可信任的资产管理流程

这条路径既不是 hacky demo，也没有重到变成 CMS。

## Interaction Model

### Library Main View

作品库首页继续保留现有卡片墙，但顶部增加两个清晰状态入口：

- `全部作品`
- `垃圾箱`

默认进入 `全部作品`。

其中 `垃圾箱` 是作品库内的**次级 scope**：

- 与 `全部作品` 共用同一页结构
- 视觉上弱于主作品目录
- 目标是可恢复、可管理，而不是展示感
- 不应与主作品目录争夺同等叙事权重

信息层级必须明确为：

1. 当前所在库域：`我的作品库`
2. 当前列表范围：`全部作品 / 垃圾箱`
3. 当前库域说明或数量摘要
4. 下方卡片墙本身

推荐结构：

```text
我的作品库
├── 标题说明区
├── scope toggle: 全部作品 | 垃圾箱
├── 当前 scope 摘要
└── 卡片墙
```

### Work Detail Modal

点击任意作品卡片后，打开一个桌面大弹窗。

弹窗必须继承现有工作台的 **result-first** 结构，而不是退化成普通左右对半分详情页。

视觉气质上，本期弹窗按**常规详情弹层**处理，而不是完全做成“缩小版工作台表面”：

- 仍保留 result-first 信息结构
- 但整体容器是清晰、稳定、居中的详情层
- 重点放在可读性和操作稳定性，而不是强展示性舞台感

这是一项有意识的取舍：优先降低实现复杂度，但接受它在气质上会比主工作台更像管理弹层。

推荐结构：

- 顶部 `master strip`
  - 封面
  - 当前展示标题
  - 来源题材
  - 风格标签
  - 音频播放器
  - 主操作：播放
  - 次操作：重命名
  - 危险操作：删除到垃圾箱
  - 次要信息：创建时间、状态说明
  - 关闭按钮
- 下方工作区
  - 左侧：节点列表
  - 右侧：节点详情 inspector

推荐信息顺序：

1. 这是哪一首作品
2. 我现在能做什么
3. 这首作品由哪些节点构成
4. 当前节点的详细内容是什么

ASCII 结构：

```text
+------------------------------------------------------------------+
| [cover] 标题 / 来源 / 风格 / 音频播放器 / 操作区 / 关闭按钮       |
|                     result-first master strip                    |
+------------------------------------------------------------------+
| 节点列表                          | 当前节点详情 inspector        |
| - 剧情提炼                        |                               |
| - 歌词结构                        |                               |
| - 编曲设定                        |                               |
| - 封面方向                        |                               |
| - 音频渲染                        |                               |
+------------------------------------------------------------------+
```

### Node Panel

下方工作区是“这首作品由哪些节点组成，以及当前节点的详情”：

- 节点列表采用现有工作台阶段顺序：
  - 剧情提炼
  - 歌词结构
  - 编曲设定
  - 封面方向
  - 音频渲染
- 默认选中第一个有内容的节点
- 如果所有节点都有内容，则从第一个阶段开始
- 节点点击后，在右侧详情区展示对应 artifact
- 不做播放式时间轴，不做自动演进动画
- 节点区必须保持 `左列表 / 右 inspector` 的工作台结构
- **禁止**把每个节点做成一张独立卡片往下堆
- **禁止**把节点详情做成手风琴式长页面展开

这块本质上是“静态创作剖面”，不是“流程回放器”。

### Rename Flow

重命名在弹窗中完成，不跳转。

推荐交互：

- 顶部标题右侧提供 `重命名`
- 点击后，标题区域**原地进入编辑态**
  - 当前标题替换为输入框
  - 右侧出现 `保存 / 取消`
  - 不再弹出二级小弹窗
- 用户可保存或取消
- 成功后：
  - 弹窗标题即时更新
  - 卡片墙对应卡片即时更新
- 失败后：
  - 输入框下方显示明确错误文案
  - 保持当前编辑态，不自动关闭或回退

重命名修改的是“作品展示标题”，默认仍映射到当前作品的 `current_result.title`。

### Delete Flow

删除动作放在弹窗顶部，但视觉上必须是次于播放的危险动作，不可过度抢眼。

推荐交互：

1. 用户点击 `删除到垃圾箱`
2. 在详情弹窗之上升起**明确的危险确认层**
   - 这是当前最上层
   - 焦点先进入确认层
   - `ESC` 先关闭确认层，而不是直接关闭详情弹窗
3. 明确文案：
   - 作品将从作品库移入垃圾箱
   - 创作节点内容暂时保留
   - 可在垃圾箱中恢复
4. 确认后：
   - 当前详情弹窗关闭
   - 作品从“全部作品”消失
   - 垃圾箱计数更新
   - 给出安全反馈：`已移入垃圾箱，可恢复`

这个反馈的目标不是“删除完成”，而是“作品已被安全收纳，仍可挽回”。

### Trash View

垃圾箱不是单独页面系统，而是作品库里的一个轻量子视图。

垃圾箱中的卡片可以更简化，但仍需保留：

- 封面
- 标题
- 删除前来源题材
- 删除时间

垃圾箱卡片点击后，打开“垃圾箱详情弹窗”或在同一弹窗中进入垃圾箱模式。

垃圾箱模式的主操作改为：

- 主操作：恢复作品
- 危险操作：彻底删除

垃圾箱作品必须沿用与正常作品**同一个详情弹窗骨架**：

- 同样的顶部 `master strip`
- 同样的下方节点列表 + inspector
- 只替换顶部主操作区文案与危险动作层级

也就是说，垃圾箱是作品状态变化，不是另一套详情系统。

推荐优先级：

- 本期必须有 `恢复`
- `彻底删除` 可以作为二级危险动作，放在更多操作或次级按钮里

## Data Model Direction

### Keep Existing Source of Truth

继续以 `generation_tasks` 作为作品和详情的事实来源。

原因：

- 当前每首作品的所有节点内容都已经在任务记录里
- 详情弹窗需要的不是新模型，而是把现有完整快照读出来
- 这能避免为“作品详情”重复建模

### Add Trash State Instead of New Trash Table

垃圾箱优先采用在任务记录上增加删除状态字段，而不是单开新表。

推荐新增字段：

- `deleted_at TEXT NULL`
- `is_trashed INTEGER NOT NULL DEFAULT 0`

语义：

- `is_trashed = 0`：作品在正常作品库里可见
- `is_trashed = 1`：作品从主作品库隐藏，只在垃圾箱可见
- `deleted_at`：记录进入垃圾箱的时间

这样做的原因：

- 不新增第二份作品记录
- 恢复操作天然简单
- 列表和垃圾箱都只是同一张表的不同投影

### Rename Semantics

重命名优先直接修改 `current_result_json.title`。

理由：

- 当前卡片标题和详情标题都来自 `current_result.title`
- 改这里可以最小改动达成 UI 一致

风险：

- 如果未来要区分“模型原始标题”和“用户手动标题”，就需要额外字段

因此建议在文档层先明确：

- v1 将重命名视为“覆盖当前展示标题”
- 后续如需保留原始标题，再补 `custom_title`

## API Shape

### Existing Endpoint (keep)

- `GET /library/works`

行为调整：

- 只返回 `status = completed AND is_trashed = 0` 的作品

### New Detail Endpoint

- `GET /library/works/{id}`

返回内容：

- 作品基础卡片信息
- 完整 `currentResult`
- 完整 `stages`
- 输入来源 `input`
- 是否在垃圾箱

这个接口本质上是“档案化详情 DTO”，不是把数据库原行直接透给前端。

### Rename Endpoint

- `PATCH /library/works/{id}`

v1 只支持：

```json
{
  "title": "新的作品标题"
}
```

行为：

- 更新 `current_result_json.title`
- 返回更新后的详情 DTO

### Move To Trash Endpoint

- `POST /library/works/{id}/trash`

行为：

- 设置 `is_trashed = 1`
- 写入 `deleted_at`

### Restore Endpoint

- `POST /library/works/{id}/restore`

行为：

- 设置 `is_trashed = 0`
- 清空 `deleted_at`

### Trash List Endpoint

- `GET /library/trash`

行为：

- 返回 `status = completed AND is_trashed = 1`
- 按 `deleted_at DESC`

### Optional Permanent Delete Endpoint

- `DELETE /library/works/{id}`

说明：

- 这个动作只对垃圾箱中的作品开放
- 仅当当前需要完整闭环时再实现
- 若本期时间紧，可先设计保留、实现延后

## Frontend State Model

前端新增三组状态：

### Library Scope

- 当前作品库 tab：`works | trash`
- 当前打开详情的作品 id
- 当前详情来源：正常作品 or 垃圾箱作品

### Modal State

- 是否打开
- 当前选中的节点
- 是否处于重命名模式
- 删除确认层是否打开

### Mutation State

- rename pending
- trash pending
- restore pending
- permanent delete pending

## UX Rules

- 打开弹窗后背景保持作品库上下文可见，但不可交互
- ESC 可关闭弹窗
- 关闭后回到用户刚才所在位置，不重置滚动
- 重命名保存成功后不关闭弹窗
- 删除到垃圾箱成功后关闭弹窗并切回卡片墙
- 从垃圾箱恢复成功后：
  - 若当前在垃圾箱视图，可保留在垃圾箱并移除该卡片
  - 若有 toast，则提示“已恢复到作品库”
- 若作品没有音频：
  - 播放按钮显示禁用态
  - 但详情仍可查看节点

## Responsive & Accessibility Spec

### Responsive

详情弹窗按桌面三档明确收缩，不接受“自适应即可”的模糊实现。

- `1440px+`
  - 使用完整大弹窗
  - 顶部 `master strip` 保持横向完整结构
  - 下方维持 `左节点列表 / 右 inspector`
- `1280px - 1439px`
  - `master strip` 继续保留横向结构
  - 缩小非关键间距与次要信息宽度
  - 节点列表略收窄，inspector 保持可读宽度
- `1024px - 1279px`
  - 弹窗仍保持桌面模式，不切成移动端抽屉
  - `master strip` 允许分成两行信息层：
    - 第一行：封面、标题、主操作、关闭按钮
    - 第二行：来源题材、风格、时间、播放器
  - 下方仍保留 `左列表 / 右 inspector`，但列表更窄，inspector 优先保留阅读空间

### Accessibility

- 打开弹窗后，键盘焦点必须进入弹窗内部
- `Tab / Shift+Tab` 必须被限制在当前弹窗上下文
- `ESC` 关闭当前最上层：
  - 若在删除确认层，先关闭确认层
  - 否则关闭详情弹窗
- 删除确认层是详情弹窗内的更高危险层，必须有清晰焦点起点
- 所有可点击节点行、scope toggle、重命名、恢复、删除按钮命中区不小于 `44px`
- 焦点态必须明显，不允许只依赖轻微边框变化
- 危险动作必须同时依赖文案与颜色，不允许只靠红色表达
- 无音频状态必须有可读文案，不允许只靠禁用样式表达

## Interaction State Coverage

| Feature | Loading | Empty | Error | Success | Partial |
|--------|---------|-------|-------|---------|---------|
| 全部作品 | 卡片墙 skeleton，保留页头与 scope toggle | 友好空态 + 主按钮“去生成第一首作品” | 页面级错误面板，提示稍后重试 | 卡片墙正常显示 | 某些作品缺少音频时显示“仅保留作品记录” |
| 垃圾箱 | 卡片墙 skeleton，保留垃圾箱标题与计数位 | 友好空态，文案同时表达“现在这里是空的”与“移入垃圾箱的作品会先存放在这里，可恢复” | 页面级错误面板，提示稍后重试 | 垃圾箱卡片墙正常显示 | 某些历史作品内容不完整时仍显示卡片，但弱化次要信息 |
| 详情弹窗 | **完整骨架态**：顶部 master strip 骨架 + 下方节点列表骨架 + inspector 骨架 | 不适用；无详情数据时应转入错误态，而不是空白态 | 弹窗内错误状态，说明作品详情暂时无法加载，并提供关闭/重试 | 正常显示作品详情与节点 | 无音频时播放器区域显示禁用/说明；缺少个别节点内容时 inspector 显示“当前步骤还没有产出内容” |
| 重命名 | 标题区域进入保存中状态，保存按钮禁用 | 不适用 | 输入框下方显示明确错误文案，不关闭弹窗 | 标题即时更新，并出现短暂成功反馈 | 若标题过长则截断显示，但 hover/focus 可见完整标题 |
| 移入垃圾箱 | 删除确认层按钮进入 pending，禁用重复点击 | 不适用 | 确认层内显示失败文案，用户可重试或取消 | 关闭弹窗，作品从全部作品消失，垃圾箱计数更新 | 若作品已被别处移入垃圾箱，则提示状态已变化并刷新列表 |
| 恢复作品 | 恢复按钮进入 pending，禁用重复点击 | 不适用 | 按钮附近显示失败文案，保留弹窗上下文 | 作品从垃圾箱移除，并提示“已恢复到作品库” | 若作品已被恢复，则提示状态已变化并刷新列表 |
| 永久删除 | 危险确认层按钮进入 pending，禁用重复点击 | 不适用 | 危险确认层显示失败文案，不自动关闭 | 成功后关闭弹窗，并提示作品已永久删除 | 若作品已不存在，则提示该作品已被删除并刷新垃圾箱列表 |

## Success Criteria

- 点击任意作品卡片都能打开详情弹窗
- 用户可以在弹窗中播放已有音频
- 用户可以在弹窗中重命名作品，且列表与详情同步更新
- 用户可以将作品移入垃圾箱
- 垃圾箱里可以恢复作品
- 详情中可以稳定查看所有已生成节点内容
- 全流程不需要跳转到新页面
