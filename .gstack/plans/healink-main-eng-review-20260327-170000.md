## Outcome

Review result: proceed with implementation.

The approved design is viable, but only if implementation keeps the workflow truthfully text-first without breaking the existing library and workspace contracts.

## Locked Decisions

1. Library compatibility

- Keep `cover_direction` and `audio_render` as real text brief stages.
- Do not keep fake media generation just to satisfy the current UI.
- Add a presentation fallback layer so completed works still appear in the library when `coverUrl` and `audioUrl` are absent.

2. Stage schema validation

- Use Pydantic models as the schema contract for each stage.
- Add `pydantic` explicitly to backend dependencies instead of relying on transitive installation through FastAPI.

3. Execution shape

- Keep `orchestrator.py` responsible for linear stage order, task state transitions, and persistence.
- Add one thin shared helper for:
  - text API call
  - `<WORKFLOW_JSON>` extraction
  - `json.loads`
  - Pydantic validation
  - same-prompt retry
- Keep stage-specific prompt construction separate from the orchestration loop.

4. Task snapshot contract

- `stages[stage].artifact` remains the only source of truth for node outputs.
- `current_result` becomes a small presentation summary only.
- Recommended `current_result` fields:
  - `title`
  - `activeStyle`
  - `currentHighlight`
  - `coverUrl`
  - `audioUrl`

5. Failure evidence

- Persist enough failure data for demo-time debugging:
  - `stage`
  - `message`
  - `retryable`
  - `attempts`
  - `failureKind`
  - truncated `lastRawOutput`

## Architecture Shape

### Runtime flow

1. Worker claims a queued task.
2. Orchestrator selects the next incomplete stage in fixed order.
3. Stage-specific code builds the prompt from:
   - `task.input`
   - required upstream stage artifacts
4. Shared text execution helper:
   - calls the text API
   - extracts JSON inside `<WORKFLOW_JSON>...</WORKFLOW_JSON>`
   - parses JSON
   - validates against the stage Pydantic model
   - retries up to the configured limit with the same prompt
5. On success:
   - persist validated artifact to `stages[stage].artifact`
   - update `current_result` summary
   - continue to the next stage
6. On terminal failure:
   - mark the stage failed
   - persist structured error payload
   - stop the task cleanly

### Recommended file ownership

- `backend/app/orchestrator.py`
  - stage order
  - task state transitions
  - retry orchestration
  - `current_result` summary updates
- `backend/app/providers.py`
  - stage prompt builders
  - text API request wrapper
- `backend/app/stage_schemas.py`
  - Pydantic models for the five stage artifacts
- `backend/app/text_workflow.py`
  - marker extraction
  - JSON parsing
  - validation
  - retry loop
- `backend/app/db.py`
  - unchanged storage table
  - library projection updated to tolerate media-less completed works

This is still a linear workflow service, not a general agent framework.

## Data Contract Changes

### Stage artifacts

Each stage artifact must validate against a dedicated schema:

- `source_analysis`
- `lyric_plan`
- `composition_brief`
- `cover_direction`
- `audio_render`

The artifact payloads are the durable business outputs.

### `current_result`

`current_result` should stop acting like a fake final media object.

Recommended semantics:

- `title`
  - primary display title, usually from `composition_brief.titleProposal`
- `activeStyle`
  - display label derived from lyric/composition direction
- `currentHighlight`
  - one short sentence that gives the workspace and library a stable textual focal point
- `coverUrl`
  - optional, only populated if a real visual asset exists later
- `audioUrl`
  - optional, only populated if a real audio asset exists later

### Library projection

Current library projection cannot remain strict about `coverUrl`.

Required change:

- library cards must still be materializable when media URLs are missing
- projection should derive stable display data from:
  - `current_result.title`
  - `current_result.activeStyle`
  - `current_result.currentHighlight`
  - source title
  - stage completion state

The presentation layer can then render a deterministic fallback cover or text-first card surface.

## Failure Model

### Failure kinds

Normalize failure classification so debugging is fast:

- `provider_error`
- `missing_marker`
- `invalid_json`
- `schema_validation`
- `unexpected_error`

### Retry policy

- First attempt plus up to 2 retries
- Same prompt each time
- Stop immediately on final failure
- User retry resets only the failed stage and downstream stages

## Implementation Order

1. Add stage schemas and shared text execution helper.
2. Replace mock stage providers with prompt-driven text stages.
3. Update orchestrator to use validated artifacts and structured failure payloads.
4. Refactor `current_result` into a presentation summary model.
5. Update library projection and serializers for media-less completed works.
6. Update frontend types/rendering to tolerate missing `coverUrl` and `audioUrl`.
7. Add tests for retry, parsing, schema failure, and library fallback rendering.

## Test Plan

### Backend unit tests

- marker extraction succeeds with exact wrapper format
- missing wrapper triggers retry then terminal failure
- malformed JSON triggers retry then terminal failure
- schema mismatch triggers retry then terminal failure
- provider exception is persisted as retryable failure
- successful retry after one failure persists only the validated artifact
- `retry_task()` clears only failed and downstream stages
- `current_result` summary updates correctly per successful stage
- media-less completed tasks still project into active and trashed library lists

### API tests

- completed workflow with no `coverUrl` and no `audioUrl` still appears in `/library/works`
- detail endpoint returns full stage artifacts and nullable media fields
- failed workflow exposes structured error payload with attempts and failure kind
- retry endpoint preserves upstream artifacts

### Frontend verification

- library card renders without crashing when `coverUrl` is null
- detail view renders text-first `cover_direction` and `audio_render` artifacts naturally
- audio controls remain disabled/hidden when `audioUrl` is absent
- workspace header still feels complete using `title`, `activeStyle`, and `currentHighlight`

## Risks

1. `lyric_plan` quality is the real demo bottleneck.

If this stage reads like generic chat output, the whole flow will feel fake even if all schemas pass.

2. Frontend currently assumes image-first cards.

The library fallback design must be implemented alongside backend contract changes, not later.

3. The approved design doc is not yet committed.

`/.gstack/plans/healink-main-design-20260327-145601.md` is still untracked in git at review time.

## Recommendation

Proceed with implementation using the locked decisions above.

Do not introduce a generic agent runtime.
Do not keep fake media outputs just to preserve current demos.
Do make the library and workspace truthfully support text-first completed works.
